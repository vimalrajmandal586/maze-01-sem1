01 / THE WHY

Why a maze?

At the end of semester one, I wanted my final project to be something a faculty member could actually use instead of just scroll through. A maze is easy to understand as a player, but interesting to explain as a programmer: cells, walls, random generation, movement, and a pathfinding hint.

“The game is simple on purpose. The thinking behind it is the interesting part.”

The browser game is the main project. There are also two companion tools in the repository: a C++ maze solver to practice classes and a Python/NumPy script to look at exported run data. They are separate programs, not secretly running on GitHub Pages.

02 / THE LOGIC

Okay, but how?

│↘│
└─┘

Each square is a cell. A cell keeps track of four walls: north, east, south and west. The player can cross an edge only when its wall has been removed.

01

Carve the maze

Start with every wall closed. Pick an unvisited neighboring cell, remove the wall between them, and keep walking. If there are no unvisited neighbors, backtrack. This is randomized depth-first search.

02

Move through it

Arrow keys, WASD, swipe, and on-screen buttons all call the same movement function. It checks the wall, updates the player's cell, and counts a step only when the move is valid.

03

Show a hint

To find the shortest route from where you stand to the exit, the game explores reachable cells layer by layer. That's breadth-first search. The resulting route appears briefly on the board.

04

Remember a run

On reaching the exit, time, steps, and hints are saved in localStorage. That's a personal record on one browser — not an online leaderboard.

WHY THERE'S ALWAYS AN EXIT ↗

Carving visits every cell and connects each newly visited cell to the maze. So there is a route between the start and finish. The hint can find it too.

03 / THE TOOLBOX

What I used.

Different subjects have different jobs here. I didn't force server-side code into a static website just to tick a box.

HTML

Three pages with navigation, game controls and build notes.

CSS

Responsive layouts, visual style, transitions and reduced-motion support.

JavaScript

Maze generation, canvas drawing, keyboard/touch input, timer and pathfinding.

jQuery

A local library copy helps handle the mobile menu and interactive page details.

C++ / OOP

A separate Maze class and breadth-first-search CLI solver for exported mazes.

Python + NumPy

A separate script summarizes JSON run data exported from the game.

PHP

Studied this semester, but deliberately not used here: GitHub Pages can't execute PHP.

The C++ and Python tools run locally from the GitHub repo. The website itself works on GitHub Pages with no backend.
